Public by design does not mean publish everything.

The public site is an allowlisted release surface. Every downloadable artifact is registered, classified, copied from a canonical source, and checked for unexpected files before publication.

Release gate

Five controls before data enter the public tree

The build treats public release as an explicit data-handling decision, not as a side effect of copying files into a web directory.

  1. MinimizeUse the least sensitive data needed for the research question.
  2. ClassifyName the unit, source, and whether person-level or immigration-status data are present.
  3. AllowlistRegister the exact canonical source and intended public destination.
  4. ReconcileRequire analytical and publication QA before release.
  5. Reject extrasFail the build when an unregistered file appears under public data or downloads.

Sensitive-data boundary

Future partner microdata start restricted, not public

Do not collect by default

Do not create person-level immigration-status fields merely because a question concerns immigrant or undocumented students. Prefer public or aggregate sources when they can answer the question.

Separate analysis from release

A dataset may be authorized for analysis without being authorized for publication. Public release requires a separate, explicit decision.

Publish approved aggregates

If restricted inputs are ever needed, only reviewed aggregate outputs should be considered for public release, subject to the actual partner agreement and disclosure rules.

Fail closed

The current build rejects unregistered files in the public data tree rather than silently serving them.
