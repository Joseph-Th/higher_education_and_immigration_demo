# Data Directory

## `raw/ipeds/`

Official NCES/IPEDS source files downloaded by `scripts/fetch_ipeds.py`.

Raw files are not committed to Git. They are reproducible from the official URLs and can be regenerated at any time.

Expected layout:

```text
data/raw/ipeds/
  2015/
    EF2015A/
    EF2015A_Dict/
    HD2015/
    HD2015_Dict/
  ...
  2024/
    EF2024A/
    EF2024A_Dict/
    HD2024/
    HD2024_Dict/
```

## `source_manifest.csv`

Tracked provenance record generated by the download script. It contains the source URL, retrieval timestamp, SHA-256 hash, file size, and extracted files for each archive.

## `schema_audit.csv`

Tracked cross-year schema check generated by `scripts/audit_ipeds_schema.py`. It records the preferred source CSV for each year, verifies the variables needed by the analysis, and confirms the `EFALEVEL` aggregation labels used for total, undergraduate, and graduate enrollment.

## `benchmark_audit.csv`

External consistency audit generated by `scripts/validate_benchmarks.py`. It compares 2019-2024 national results with selected rows from NCES Digest 2025 Table 306.10 and records the current value, published rounded value, difference, threshold, release status, and pass/fail result for 24 metric-year checks.

## `reference/`

Independent validation inputs that are not used to generate the analysis. The current reference is a compact transcription of selected values from NCES Digest 2025 Table 306.10, with its own provenance note.

## `research_library.csv`

Structured metadata for the external resources used to collect, interpret, validate, and maintain the project. It records a stable resource ID, title, publisher, resource type, population/topic tags, workflow stage, scope, update pattern, project role, URL, last-checked date, and status note. `scripts/build_research_library.py` validates the schema and generates both `docs/RESEARCH_LIBRARY.md` and the searchable `site/research-library.html` interface.

## `source_update_triage.csv`

R07 source-change routing register covering every `resource_id` in `research_library.csv` exactly once. Each row records the source's expected baseline route, the event that normally starts that route, conditions that escalate to methodology review, conditions that justify reviewing a new research question, the affected portfolio surface, and an interpretation boundary. `scripts/build_source_update_triage.py` fails when library coverage is incomplete or duplicated and generates `docs/SOURCE_UPDATE_TRIAGE.md` plus `site/source-update-triage.html`. Publication dates and URL changes are review signals, not inferred partner deadlines or automatic evidence of a changed conclusion.

## `undocumented_pipeline_reference.csv`

Fixed-vintage R06 public aggregate reference containing one 2023 national row plus ten states with explicit values in both source surfaces. It preserves annual undocumented high-school graduate estimates, undocumented higher-education enrollment estimates, separate Research Library authorities/URLs, and source notes. The file contains no individual records and deliberately distinguishes annual flow from enrollment stock.

## `undocumented_pipeline_comparison.csv`

Generated 10-state ecological comparison built by `scripts/build_undocumented_pipeline.py`. It calculates separate national shares, within-overlap ranks, and a descriptive stock/annual-flow scale multiple, then generates `docs/UNDOCUMENTED_PIPELINE_CONTEXT.md` and `site/undocumented-pipeline.html`. The scale multiple is explicitly not a college-going, transition, persistence, or causal rate.

## `publication_handoff.csv`

Generated pre-publication claim register. Each row maps reviewer-facing copy to its canonical project authority, field/row locator, maintained Research Library source, QA gate, required disclosure, and publication status. It is not an input to the analysis and does not claim to represent the Presidents' Alliance's internal approval workflow. `scripts/build_publication_handoff.py` regenerates the CSV, `docs/PUBLICATION_HANDOFF.md`, and `site/publication-handoff.html` from validated current outputs.

## `public_release_register.csv`

Structured authority for the public download tree. Each row names a canonical source, public destination, data class, unit of record, person-level/immigration-status flags, release basis, release rule, and decision. The current PUBLIC register contains no person-level records or observed immigration-status data. `scripts/build_data_governance.py` validates the register and generates the human-readable/data-governance page; `scripts/build_site_data.py` publishes only registered artifacts and fails if any unregistered file appears under `site/downloads/` or `site/data/`.

## `research_agenda.csv`

Structured research-needs register. Each row records a stable research ID, priority, research question, evidence trigger, whether the current IPEDS pipeline can answer it, additional data needs, proposed method/output, decision rule, and current status. `scripts/build_research_agenda.py` validates the register and generates `docs/RESEARCH_AGENDA.md`.

## `population_crosswalk.csv`

Structured methodology/source-selection control for six distinct immigration-related student concepts: IPEDS U.S. nonresident, immigrant-origin, SEVIS international, undocumented higher-education, undocumented high-school-graduate, and refugee/asylee students. Each row records the measure type, primary source and vintage, unit, inclusion/exclusion rules, geography, best use, comparison warning, project status, source URL, and review date. `scripts/build_population_crosswalk.py` validates the crosswalk and generates both `docs/POPULATION_CROSSWALK.md` and the public `site/methodology-crosswalk.html` page.

## `population_trend_reference.csv`

Curated public aggregate observations used by the bounded R04 comparison. It contains no person-level data. Each row retains the population definition, observation year, published estimate/share where available, source vintage, method-compatible `trend_segment`, source-reported change where applicable, Research Library foreign key, URL, and interpretation note. Historical and current undocumented estimates intentionally use separate trend segments until model equivalence is established.

## `population_trend_comparison.csv`

Generated national comparison table built by `scripts/build_population_trends.py` from the canonical 2019-2024 IPEDS national series plus `population_trend_reference.csv`. It calculates change only within compatible segments and generates `docs/POPULATION_TREND_COMPARISON.md` plus `site/population-trends.html`. Cross-population values are scale context only and are never added into a combined immigration-related enrollment total.

## `recurring_report_register.csv`

Portfolio operations register for the three recurring research products named in the target role. Each row foreign-keys to both a `population_id` in `population_crosswalk.csv` and a `research_library_id` in `research_library.csv`, then records public-product vintage, guarded schedule status, partner context, intake requirements, methodology-change checks, QA gates, publication outputs, and the next kickoff action. The register deliberately requires the schedule text to say that milestones must be confirmed with the partner instead of inventing an internal deadline from public publication dates. `scripts/build_recurring_report_register.py` validates those relationships and generates `docs/RECURRING_REPORT_REGISTER.md` plus `site/research-operations.html`.

## `production_cycle_register.csv`

Seven-row shared stage-gate authority for recurring partner research. Each stage records the generic coordination role, entry condition, required record, blocker, exit condition, next-stage handoff, and retained evidence. It is deliberately date-free and person-free until a real partner kickoff occurs. `scripts/build_production_cycle.py` validates the stage sequence and joins it to the three product-specific recurring-report records to generate `docs/PRODUCTION_CYCLE.md` and `site/production-cycle.html`.

## `production_cycle_log_template.csv`

Intentionally empty 16-field CSV template for the live coordination record described by the production-cycle controls. `scripts/validate_production_cycle_log.py` validates populated copies against the three recurring `report_id` values, seven production `stage_id` values, controlled record types/materiality/status values, ISO dates, terminal/active closure rules, and approval/hold decisions. The tracked blank template is public; completed partner logs are nonpublic by default and must stay in the approved working location unless a separate release review authorizes disclosure.

## `sql_analysis_audit.csv`

One row per public SQL portfolio query. The audit records the query ID/title, demonstrated SQL skills, returned row count, independently calculated expected value, observed SQL value, status, and reconciliation note. `scripts/build_sql_analysis.py` rebuilds an in-memory SQLite database from five canonical processed CSVs, executes `sql/portfolio_queries.sql`, rejects non-read-only SQL, and fails if any expected/observed check differs. No SQLite database file is stored or published.

## `ad_hoc_analysis_results.csv`

Three generated rows representing explicitly simulated one-off management questions. Each row records the business question, generic decision use, concise answer, supporting detail, validated source authority, reconciliation check, and `PASS` status. `scripts/build_ad_hoc_analysis.py` calculates the answers from the canonical state/control/national CSVs and generates `docs/AD_HOC_ANALYSIS.md` plus `site/ad-hoc-analysis.html`. The scenarios contain no real requester, deadline, SLA, or client/employment-history claim.

## `planning_scenarios.csv`

Four generated rows for planning support: one 2024 backtest and three 2025 planning cases. The backtest applies the 2021-2023 CAGR to the 2023 actual, records the resulting 2024 baseline, and compares it with the known 2024 actual. The forward cases apply three transparent historical growth windows to the 2024 actual and deliberately leave future actual/variance fields blank. `scripts/build_planning_scenarios.py` generates the CSV, `docs/PLANNING_SCENARIOS.md`, and `site/planning-scenarios.html`; the artifact is a planning exercise rather than a predictive model.

## `release_monitor_snapshot.json`

Dated output from `scripts/check_for_new_release.py --write-snapshot ...`. It records the current analysis end year, candidate next year, UTC check timestamp, HTTP availability/status for the four required candidate-year IPEDS package assets, component readiness, complete-package readiness, and the resulting year-advance decision. It is updated only by an explicit online check; the offline validation lane never performs the network request itself.

## `freshness_monitor.csv`

Ten generated monitoring rows combining the captured NCES release observation with maintained Research Library, population-crosswalk, and recurring-report review metadata. The register contains four candidate-file observations, one annual year-advance gate, two source-review controls, and three recurring-product monitoring triggers. `scripts/build_freshness_monitor.py` writes the CSV, `docs/FRESHNESS_MONITOR.md`, and `site/freshness-monitor.html` without inventing deadlines or treating a working URL as a completed methodology review.

## `release_readiness.csv`

Eight generated release controls built by `scripts/build_release_readiness.py`. Seven gates govern whether the current validated publication may remain public; one gate governs whether the configured analysis year may advance. The matrix combines analytical QA, NCES benchmark status, complete high-priority institution review, publication handoff, public-release registration, PDF/PowerPoint freshness, Research Library routing coverage, and the dated candidate-year package observation. A current decision of `READY_WITH_CLAIM_LEVEL_HOLDS` preserves institution-specific narrative holds without invalidating aggregate publication, while `HOLD_YEAR_ADVANCE` keeps `END_YEAR` unchanged until the complete candidate package can enter schema review. The builder also writes `docs/RELEASE_READINESS.md` and `site/release-readiness.html`.

## `qa_resolution_log.csv`

Manually curated analyst dispositions for every high-priority row in `processed/latest_release_institution_review.csv`. The log records the institution, review date, disposition, publication class, outside evidence URL, and an analyst note. It never changes an IPEDS source value. `scripts/build_qa_resolution_log.py` requires complete current high-priority coverage and generates `docs/QA_RESOLUTION_LOG.md`, `qa_resolution_summary.json`, and `site/qa-review.html`.

## `processed/`

- `national_year.csv`: 2015-2024 national trend used by the public brief.
- `state_year.csv`: state-by-year aggregates for the 50 states and DC.
- `state_change_summary.csv`: one-row-per-geography comparison for 2015, 2019, and 2024, including recovery status.
- `state_profile_index.csv`: one-row-per-geography publication index with latest counts/shares, long-run and post-2019 changes, latest annual change, graduate share, leading institution, and generated profile filename.
- `control_year.csv`: public, private nonprofit, and private for-profit aggregates by year.
- `institution_change_summary.csv`: endpoint UNITID panel that decomposes the 2015-2024 national change into continuing institutions and analytic-universe entry/exit.
- `latest_release_institution_review.csv`: newest-year institution comparison with deterministic review priority and reason fields.
- `institutions_2024.csv`: latest-year institution detail in the analytic universe.
- `institution_year.csv`: full normalized intermediate dataset; reproducible and intentionally ignored by Git because of size.

## JSON summaries

`qa_report.json` records the analytic universe, per-year source files, row counts, imputation-flag distributions, excluded jurisdictions, and structural/arithmetic check results.

`findings.json` is a compact machine-readable summary used to build the public research brief.

It includes national headline metrics, level-change decomposition, state recovery relative to 2019, institutional-control change, institution-universe dynamics, state and institution concentration, state rankings, latest institution detail, and the national time series.

`latest_update_review.json` is the newest-release review summary used by the public brief and generated review memo. It contains the newest national change, undergraduate/graduate decomposition, institution-universe accounting, state movers, review-priority counts, top review items, and imputation/status transitions.

`qa_resolution_summary.json` is the compact publication summary of the manual QA disposition layer. It records the full high-priority queue size and coverage percentage, counts classified as `safe_with_context` versus `hold_for_confirmation`, disposition counts, and three deterministic featured case studies used by the public brief and research memo. It is generated from `qa_resolution_log.csv` only after the log has been reconciled to every current high-priority queue record.

`state_profiles.json` is the machine-readable state-publication product generated from validated state and institution outputs. It contains one profile for each of the 50 states plus DC with current metrics, change windows, top institutions, and the 2015-2024 annual series. `site/state.html` reads this file to provide shareable state views; generated Markdown counterparts live in `docs/state_profiles/`.
